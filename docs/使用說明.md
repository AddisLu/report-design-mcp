## 1. 這套工具在做什麼

直接叫模型寫報告常常不像樣，原因是一次就要它讀資料、算數字、寫內容、排版面。這套工具把工作拆開，各自交給最適合的角色：

| 工作 | 誰負責 | 效果 |
|---|---|---|
| 讀 Excel／CSV／Word／PPT／PDF、計算數字 | Python 程式 | 數字不會算錯，也無法捏造 |
| 依受眾決定重點與故事線、寫結論句 | Copilot 的模型 | 主管版、經理版、工程版的觀點不同 |
| 字型、顏色、位置 | 公司範本 | 版面不會跑掉 |
| 文字放不下、用語、空泛詞 | 自動檢查與修正 | 少了一輪又一輪的來回 |

完整流程只需要 **2 次工具呼叫**：

```
你：「用 Q3.xlsx 做給主管看的報告」
  └─ Copilot 呼叫 get_design_context（一次拿到規則、版型、資料、草稿）
  └─ Copilot 寫出 spec，呼叫 build_deck（檢查＋修正＋產出 .pptx）
你：拿到 output\Q3報告_executive.pptx
```

## 2. 安裝（離線）

需求：Windows 11、**64 位元 Python 3.8**。公司連不到 PyPI 也沒關係，所有套件都放在 `wheelhouse/` 裡。

```bat
git clone https://github.com/AddisLu/report-design-mcp.git
cd report-design-mcp
install_offline.bat
```

`python` 不在 PATH，或預設不是 3.8 時，請指定路徑：
```bat
install_offline.bat C:\路徑\python.exe
```

腳本會依序：檢查 Python 版本與位元數 → 建立 `.venv` → 離線安裝套件 → 執行 smoke test。最後看到 **`ALL PASSED`** 就是安裝成功。

> 查自己的 Python 是幾位元：`python -c "import struct;print(struct.calcsize('P')*8)"`，結果應該是 `64`。

## 3. 掛到 VS Code 的 Copilot

### 在這個資料夾裡使用（最簡單）
1. 用 VS Code 開啟 `report-design-mcp` 資料夾。
2. VS Code 會讀取 `.vscode/mcp.json`，啟動名為 `report-design` 的 MCP server。如果跳出「是否信任／啟動」的提示，請允許。
3. 開啟 Copilot Chat，切到 **Agent** 模式，點工具圖示，確認有以下 7 個工具：
   `get_design_context`、`build_deck`、`patch_deck`、`read_sketch`、`get_sketch_canvas`、`save_layout`、`inspect_template`
4. `.github/copilot-instructions.md` 會自動告訴 Copilot 工作流程，不必每次說明。

### 在其他專案資料夾也要用
把下面設定放到該專案的 `.vscode/mcp.json`，或 VS Code 的使用者層級 MCP 設定。路徑請改成你 clone 的位置：

```json
{
  "servers": {
    "report-design": {
      "type": "stdio",
      "command": "C:/Coding/report-design-mcp/.venv/Scripts/python.exe",
      "args": ["C:/Coding/report-design-mcp/mcp_server.py"],
      "env": { "PYTHONIOENCODING": "utf-8" }
    }
  }
}
```

### 一鍵 prompt
在 Copilot Chat 輸入 `/` 就能選用：

| prompt | 用途 |
|---|---|
| `/report-from-sketch` | 依手繪草稿＋資料做報告 |
| `/exec-report` | 主管版報告（≤ 8 頁，結論先行） |
| `/project-review-mgr` | 經理版專案檢討（問題專案每案一頁） |

## 4. 第一次設定：換成公司範本與文風

### 4.1 放入公司範本
```bat
copy 公司範本.pptx design_system\templates\
.venv\Scripts\python cli.py inspect design_system\templates\公司範本.pptx --set-default
```
也可以直接在 Copilot 說：「解析 design_system\templates\公司範本.pptx 並設為預設」。

`.pptx` 和 `.potx` 都可以用。範本裡原有的範例投影片會自動清掉，只使用母片與版型。

### 4.2 補上版型用途說明（建議）
打開 `design_system/layout_catalog.json`，把每個版型的 `use` 改成公司的實際用法，例如：

```json
{ "key": "標題及內容", "use": "一般內容頁：條列，或一張圖表" },
{ "key": "兩欄比較", "use": "左文字右圖表；或方案 A／B 比較" }
```
模型會依這些說明挑選版型。之後就算範本更新，你寫的說明也會保留。

### 4.3 放一份「好報告」範例（效果最明顯）
在 `design_system/examples/` 放 1–2 份你認為寫得好的報告 spec，檔名包含受眾，例如 `executive_月報.json`。模型會照著它的寫法來做。格式請參考內附的 `executive_example.json`。

## 5. 日常使用：三種做報告的方式

### 方式 A：只有資料
> 用 data\Q3專案.xlsx 做一份給主管看的進度報告

### 方式 B：資料＋手繪草稿
> 照 sketches\q3.pdf 的草稿，用 data\Q3專案.xlsx 和 data\週報.docx 做給經理看的報告

### 方式 C：用已存版型
> 用「月報-主管版」版型，資料是 data\10月.xlsx

### 受眾怎麼說
| 說法 | 對應 | 規則重點 |
|---|---|---|
| 主管、高階主管、老闆、總經理、處長 | `executive` | ≤ 8 頁、每頁 ≤ 3 條、結論與決策先行 |
| 經理、部門主管、專案經理、PM | `manager` | ≤ 15 頁、每頁 ≤ 5 條、進度＋對策＋負責人 |
| 工程師、技術團隊、RD、研發 | `engineer` | ≤ 25 頁、可放細節、根因與待辦 |

同一份資料可以分別做三個版本，只要換一個受眾說法即可。資料讀過一次會快取，第二次更快。

### 完成後會看到
- 檔案路徑：預設存在 `output\報告名_受眾.pptx`，旁邊還有一個 `.spec.json`（修改時會用到）
- 頁面對照：spec 第幾頁對應到投影片第幾張（重複頁、續頁會展開）
- **註解解讀表**：草稿上每條手寫註解被辨識成什麼、怎麼套用
- 提醒：例如「數字沒有引用資料」「條列太長」「用語偏空泛」

## 6. 手繪草稿怎麼畫

### 6.1 產生底稿
> 給我 8 頁草稿底稿，存到 sketches\canvas.pdf

或執行：
```bat
.venv\Scripts\python cli.py canvas sketches\canvas.pdf --pages 8
```
第 1 頁是**需求頁**，後面是 **12×8 格線的版面頁**（比例和投影片相同）。把 PDF 匯入手寫板 App（GoodNotes、Notability、OneNote、Samsung Notes 等）當底圖。

### 6.2 筆色規則（最重要）
| 筆 | 畫什麼 | 會怎麼處理 |
|---|---|---|
| **黑筆** | 版面框線，框內寫類型 | 變成投影片上的區塊 |
| **紅筆**（或其他彩色筆） | 你的註解、要求 | 當作給模型的指示，**不會印在投影片上** |

框內可寫的類型：

| 寫 | 意思 |
|---|---|
| 標題 | 頁標題 |
| 結論 | 一句話結論（大字） |
| KPI | 大數字指標卡 |
| 圖（可加「長條」「折線」「圓餅」） | 圖表 |
| 表 | 表格 |
| 重點 | 條列 |
| 圖片 | 圖片 |
| 備註 | 小字附註 |

框裡只要寫類型，不必寫內容。內容會依資料和受眾自動產生。

### 6.3 頁面標記
| 位置 | 寫什麼 | 效果 |
|---|---|---|
| 左上角 | `需求` | 這頁不產生投影片，內容當作整份報告的要求（受眾、目的、資料、重點） |
| 左上角 | `×每個專案`、`×每個部門`、`×N` | 重複頁：依資料每個專案（部門…）各展開一張 |
| 左上角 | 不寫或寫 `版面` | 一般版面頁，一頁草稿＝一張投影片 |
| 右上角 | `P3` | 頁碼，決定順序 |
| 任意位置 | `插在 P2 後` | 調整順序 |

### 6.4 註解寫法範例
| 你寫的紅筆註解 | 效果 |
|---|---|
| 「延遲的標紅」（箭頭指向 KPI） | 延遲專案的數字變紅色 |
| 「只講有問題的」（指向重點框） | 條列只列異常專案，其餘一句帶過 |
| 「用折線，看趨勢」（指向圖框） | 改成折線圖 |
| 「這頁給老闆看，只講結論」 | 整頁精簡成結論 |
| 「"本季目標達成"」（加引號） | 引號內的文字原樣放進投影片 |

### 6.5 提高辨識率的小技巧
- 框線畫成封閉的四邊形
- 類型字用印刷體，字不要太小
- 每頁右上角都寫頁碼
- 很多頁時匯出成**一份多頁 PDF**；超過約 15 頁時，Copilot 會自動分批讀取

## 7. 修改報告

直接用口語說要改哪裡，Copilot 會用 `patch_deck` **只改那幾頁**，其他頁完全不動：

> 第 3 頁標題改成「B 案需追加外包」
> 第 2 頁那條註解是「延遲」不是「延期」，重做那頁
> 刪掉第 5 頁，在第 2 頁後面加一頁風險清單

> 「第幾頁」指的是 spec 頁碼，也就是完成時「頁面對照」的左欄。如果有重複頁或續頁，投影片張數會比 spec 頁數多。

> 如果 .pptx 正在 PowerPoint 開啟，系統會自動另存成 `檔名 (2).pptx`，不會失敗。

## 8. 存成可重複使用的版型

滿意某份草稿的版型時：
> 把這份草稿的版型存成「月報-主管版」

只會存框線位置、類型，以及「每次都適用」的指示，不會存這次的內容或一次性的註解。如果某條註解每次都要用（例如「延遲一律標紅」），請在存檔時一併說明。

之後：
> 用「月報-主管版」做 10 月的報告，資料在 data\10月.xlsx

就不必再畫。已存版型記錄在 `design_system/blueprints.json`。

## 9. 資料來源與數字引用

### 支援的檔案
| 類型 | 副檔名 | 變成 |
|---|---|---|
| 表格 | `.xlsx` `.xlsm` `.csv` `.tsv` | 表格 `t1`、`t2`…（每個工作表一個），可引用數字 |
| 文件 | `.docx` `.pptx` `.pdf` `.md` `.txt` | 文字 `d1`…；裡面的表格、PPT 圖表資料也會轉成 `t#` |
| 資料夾 | — | 自動讀取裡面所有支援的檔案 |

- CSV 會自動判斷 UTF-8 或 Big5（cp950）編碼
- Excel 會自動跳過頂端的標題列，找到真正的表頭
- `80%` 這類百分比會自動辨識，比較或計算時不必換算
- 舊版 `.xls` 請先另存成 `.xlsx`

### 數字為什麼一律用引用
模型寫的是 `{t1[代號=B].實際進度}`，而不是自己打「61%」。產出時由程式代入真實數字，所以：
- 不會算錯、抄錯，也無法捏造
- 引用寫錯時（找不到欄位或資料列）不會產出，會明確告訴模型要修哪裡

引用語法（給進階使用者參考，平常不必自己寫）：

| 寫法 | 意思 |
|---|---|
| `{t1[專案=B].交付率}` | 單一儲存格 |
| `{t1.營收.sum}` | 合計（另有 `.mean` `.min` `.max` `.median` `.count` `.distinct` `.first` `.last`） |
| `{t1[部門=A][狀態=延遲].count}` | 多條件篩選後計數（可用 `!=` `>` `<` `>=` `<=` `~` 包含） |
| `{=t1[代號=B].目標 - t1[代號=B].實際}` | 四則運算 |
| `{… \| .1%}` | 指定格式 |
| `**文字**`、`!!文字!!` | 強調色、紅色警示 |

## 10. 自訂設計系統

所有設定都在 `design_system/`，改完立即生效，不必重新啟動：

| 檔案 | 用途 |
|---|---|
| `config.json` | 預設範本、預設受眾、警示顏色（預設 `C00000` 紅）、最小字級、輸出資料夾 |
| `audiences/*.yaml` | 各受眾的頁數上限、條列數與字數、結構、重點、避免事項、語氣。可以新增，例如 `board.yaml`（董事會版） |
| `style_guide.md` | 公司文風說明（模型會讀） |
| `style_rules.yaml` | 自動替換用語（例如 信息→資訊）、空泛詞提醒、禁用詞 |
| `examples/*.json` | 好報告範例 |
| `templates/` | 公司範本 |
| `layout_catalog.json` | 版型清單與用途說明（自動產生，可手動改 `use`） |
| `blueprints.json` | 已存的手繪版型 |

## 11. 不能用 MCP 時：CLI

如果公司 policy 停用了 Copilot 的 MCP，同一套功能可以用命令列執行，也能請 Copilot 在終端機代為執行：

```bat
:: 看模型會讀到的完整情境（可加 --sketch 草稿.pdf）
.venv\Scripts\python cli.py context --audience 主管 --sources data\Q3.xlsx

:: 依 spec 產出投影片
.venv\Scripts\python cli.py build my_spec.json -o output\

:: 修改指定頁（patch.json 格式：{"slides": {"3": {"title": "…"}}, "delete": [5]}）
.venv\Scripts\python cli.py patch output\報告_executive.spec.json patch.json

:: 產生草稿底稿、解析範本
.venv\Scripts\python cli.py canvas sketches\canvas.pdf --pages 8
.venv\Scripts\python cli.py inspect design_system\templates\公司範本.pptx --set-default
```

## 12. 疑難排解

| 狀況 | 處理方式 |
|---|---|
| `install_offline.bat` 說需要 64-bit Python 3.8 | 用 `install_offline.bat C:\路徑\python.exe` 指定正確的 Python；如果公司只有 32 位元版，請告知，需要另外準備 win32 套件 |
| pip 說找不到某個套件版本 | 確認 `wheelhouse/` 有完整 clone 下來（10 個 `.whl` 檔） |
| Copilot 工具清單沒有 `report-design` | ① 確認是 **Agent** 模式 ② VS Code 指令面板執行「MCP: List Servers」，查看 `report-design` 的狀態與 log ③ 確認 `.venv\Scripts\python.exe` 存在 ④ 公司可能用 policy 停用 MCP，請改用 [CLI](#11-不能用-mcp-時cli) |
| MCP 啟動失敗 | 在終端機執行 `.venv\Scripts\python mcp_server.py`：沒有錯誤訊息、游標停住等待輸入，就是正常（按 Ctrl+C 結束） |
| Copilot 沒用工具，自己寫 python-pptx 程式 | 明確說「用 report-design 工具」，或改用 `/exec-report` 等一鍵 prompt |
| 產出的投影片字型不對 | 範本的主題字型沒設定中文字型；請在範本的「設計 → 變化 → 字型」設定，或在 `config.json` 設定 `builtin_font_ea`（只對內建範本有效） |
| 文字超出框線 | 已自動縮字或拆續頁，提醒中會列出；請 Copilot 精簡該頁，或改用更大的區塊 |
| 手寫註解辨識錯誤 | 看「註解解讀表」，直接告訴 Copilot 正確的字，它只會重做那頁 |
| 圖片草稿傳不進去 | 部分 Copilot 版本不顯示工具回傳的圖片；可改在聊天中直接附上草稿圖片 |
| 執行 smoke test 失敗 | 把完整輸出貼給維護者 |

## 13. 常見問題

**Q：一定要用公司範本嗎？**
不用。沒有範本時會自動使用內建的 16:9 簡潔範本。

**Q：會把公司資料傳到外面嗎？**
這套工具本身完全在本機執行。資料摘要會交給 Copilot 的模型閱讀，和你平常把檔案貼給 Copilot 一樣，請依公司的 Copilot 使用規範處理機密資料。

**Q：可以只做其中幾頁嗎？**
可以，說「只做第 2–4 頁」即可；草稿頁數很多時，也可以分批讀取。

**Q：可以產出 Word 或 PDF 嗎？**
目前只產出 PowerPoint。PDF 可以用 PowerPoint 另存。

**Q：OpenProject 的資料怎麼用？**
第二版會直接接 OpenProject API。在那之前，請先從 OpenProject 匯出 CSV 或 Excel，當作資料來源。

**Q：可以新增其他受眾，例如董事會版？**
可以。複製 `design_system/audiences/executive.yaml` 成 `board.yaml` 修改內容，並在 `aliases` 加上「董事會」，之後說「做董事會版」就會套用。
